## 原因と最小修正

勤務先0件のとき `renderSettingsJobTabs` が選択先を未定義にし、その後 `getSettingsFormHtml` が存在しない勤務先の `.name` を参照して停止していました。

- `renderSettingsJobContent`：有効な勤務先名がなければ表示領域を空にして終了。
- `getSettingsFormHtml`：存在しない勤務先も空文字を返す。
- `loadSettingsToUIForTab`：有効な勤務先がなければ読み込みを終了。

架空の勤務先の自動登録や、保存データの補完・書き換えは行いません。新規登録欄は既存UIのまま利用できます。CSS・給与計算・保存関数・データ形式・LINE認証・Supabase処理には変更がありません。

## 公開範囲と承認待ちの操作

現在は外部向けURLを発行しておらず、Cloudflareへのアップロードも行っていません。

許可後は **新規のテスト専用Cloudflare Pagesプロジェクト**へ、この静的プレビューだけを手動配置する予定です。Git自動連携は使いません。既存のPagesプロジェクト・公開URL・設定、本番／LINE版、mainは変更しません。

通常のPages公開では、URLを知っている人はログインなしで閲覧・操作できます。`noindex` は設定済みですが、アクセス認証ではありません。公開されるのはプレビューのコード・フォント・架空データのみで、実データや実サービスにはアクセスできません。登録操作は各閲覧者のページ内メモリーだけに反映されます。ホスティング先が通常記録するアクセスログまで無くなるという意味ではありません。

新規プロジェクトの作成、アップロード、URL発行は、公開範囲と安全性を確認いただいてからの別途許可待ちです。

実機Android／OS固有の選択メニュー、実際のLINE・Supabase・決済は未検証です。今回の確認はローカルChromiumで行いました。
