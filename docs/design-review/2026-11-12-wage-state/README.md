# 時給入力・土日祝加算下の登録ボタン：保存状態の修正

対象：PR #8 / `design/bordeaux-rose-champagne`。修正前は a6295ff。実機ではなく、ChromiumのAndroid相当モバイル設定・320×568 / 375×812・DPR 2で撮影。架空の勤務先・時給のみ使用し、LINE/Supabaseはモック。実サービスへの書き込みなし。

## 原因と現在の状態の見分け方

起動時に保存済みの時給データを読み込んだ行が白文字になること自体は正常です。一方、修正前は再描画時に「開始・終了・時給が入力済み」だけで保存済みクラスを付与していました。このため、新規入力や土日祝加算の変更後に、行追加や勤務先切り替えで再描画すると、登録成功を確認せず白文字に戻りました。利用者の端末内データそのものは確認していません。

保存確認状態をページ内メモリーで管理し、勤務先ごと・行ごとに入力内容と照合するよう修正しました。入力変更／新規行は金色、既存の保存処理が成功した場合のみ白色、保存失敗・入力エラーは金色を維持。行削除で番号がずれた場合も対応し、設定全体の保存成功も表示に反映します。

保存フラグを保存データに追加していません。従来の自動保存の動作も維持しています。このため金色はこのページ内での「登録確認待ち」を示し、自動保存まで停止している意味ではありません。再起動時は保存されているデータを初期状態として扱います。

## 検証結果

- 両幅・修正前後それぞれで4状態を検証。文字色と `-webkit-text-fill-color` を両方検査。光沢背景は全状態で同一。
- 新規空行は金色、起動時の保存済み行は白色。
- 行追加・勤務先切り替え・保存失敗後の再描画でも状態を維持。
- 別行の削除で対象行の番号がずれても金色を維持。再登録成功後は白色。
- 設定全体を正常保存し、画面を再度開いた場合も白色。
- 320px・375pxの対象行とボタンは文字切れ・重なりなし。JavaScript実行エラーなし。
- アプリ回帰検証：14 scriptの構文、承認済み表示差分を除く既存スクリプトとの一致、25件のレイアウト、給与・深夜計算、登録／再読み込み、設定自動保存、バックアップ・認証・期限切れ制御（モック）、勤務先0件などが成功。[結果](functional-results.json)
- CSSは修正前と完全一致。給与計算、保存処理本体、保存スキーマ、認証処理、採用済みデザインは変更なし。

再現用：`node tests/wage-registration-state.cjs`（ローカル8826でリポジトリを配信）。[状態の検証結果](results.json)。実Android端末・実認証・実クラウド連携は未検証です。
