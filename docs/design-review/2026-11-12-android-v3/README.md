## 設定の保存仕様：閉じるボタンは残しています

すべてが無条件に自動保存されるとは確認できなかったため、削除条件を満たしませんでした。保存処理を変更せず、既存のボタンを維持しています。

|確認事項|結果|
|締め日・給料日・有給単価・交通費・その他・手当名・時給・加算額|input/changeでメモリへ同期し、最後の入力から500ms後に保存。両幅で10項目を保存データと照合|
|下部タブで移動|保存待ちタイマーは残り、保存完了後の再起動でも保持|
|バイト先名の新規入力|文字を入力しただけでは登録されず、既存の「登録」ボタンが必要。登録成功後は再起動で保持|
|入力直後に再読み込み|500msの保存待ち中は、メモリの変更と保存済みデータが異なり、再読み込みで直前の変更が失われることを再現|
|閉じるボタン|入力直後でもsaveSettingsを実行。成功時に移動し、失敗時は設定を開いたまま警告を表示|
|自動保存失敗|保存済みデータは変わらず、未完了の警告が表示され、保存ボタンは金文字のまま|
|既存の時給行削除の失敗|保存失敗警告が出る一方、「時間帯を削除しました」も表示される。メモリ上では削除、保存済みデータでは未削除。この既存の不一致も両幅で再現|

[自動保存の検証コード](autosave.cjs)／[結果](autosave-results.json)／[失敗時の画面](320-autosave-failure.png)／[既存の削除失敗時の画面](320-existing-delete-failure.png)

**次の対応案（今回は未実施）**：時給行削除の完了表示を保存成功時だけに限定し、失敗時のメモリ状態と再試行方法を整理すること、保存待ちの終了・再読み込みへの対策を検討すること。そのうえで「閉じる」の削除可否を改めて判断します。保存処理の変更はユーザー確認後に別途行います。
