# 端末保存・排他設計

サーバーが受理した同一LINE ID tokenのiss/subを取り出し、subのSHA256でアカウント別キーを作ります。JWTの復号は署名検証ではなく、署名検証は既存サーバーが担当します。トークンは保存しません。認証完了までは旧データを画面へ出しません。

編集画面はアカウントごとのWeb Lockを文書の寿命中保持します。第二画面は閲覧専用。第一画面を閉じ、再確認して最新状態を読み直せます。保存時は読み込んだraw値とリビジョンを確認し、一回のJSON書込で更新します。リビジョン比較だけを原子的排他とみなしていません。

競合でDOMと編集中状態を自動破棄しません。再確認時に入力破棄を明示確認し、キャンセルで保持します。ブラウザー非対応は閲覧のみ。Web Locksの実Android対応、LINE内ブラウザー、バックグラウンド停止からの復帰は実機検証が残ります。

同一端末の別LINEアカウントは別キー。変更検出時にはアプリ内容を隠し、保存・復元・書出しを止めます。非同期の認証/ハッシュ計算・クラウド応答前後も再検査します。元アカウントへ戻す場合を除き、再読込が必要です。

旧キーの所有者が不明な場合、自動引継ぎせず本人の明示確認を要求します。旧キーは削除しません。一度確認した所有者のハッシュを記録し、別アカウントへ移しません。旧データの所有権をサーバーで証明したわけではない点は制限です。日時等の補助メタデータも所有者別です。

ローカルストレージは端末/ブラウザーの領域です。手動消去や機種変更から保護するものではありません。バックアップ形式はschemaVersion2のまま、所有者・保存リビジョンを含めません。
