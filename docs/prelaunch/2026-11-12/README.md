# 販売前8件の修正・検証

対象ブランチ: `fix/prelaunch-integrity`。基準は PR #8 の `0801e96568684b45444cee9033d200bc2501099e`（承認済みv4）。main、PR #8の作業ブランチ、公開URL、DB・LINE・決済の設定は変更していません。

## 修正結果

|項目|対応と確認|
|---|---|
|1. 設定変更が過去の給与に波及|時給・時間帯・曜日加算・有給単価・交通費・手当を適用開始日付きの履歴に保存。初回も日付の明示選択が必要。過去に影響する変更は再計算への確認を要求。|
|2. 登録エラーの時給が計算に使用される|入力途中の設定は永続化する下書きに分離。検証と日付確定が成功した設定だけを計算に使用。重複・不完全な時間帯を適用しない。|
|3. 勤務時間以上の休憩|手入力・ワンタッチ登録・休憩編集・バックアップ読み込みで拒否。休憩は勤務時間未満の整数分。|
|4. 開いたまま無料体験期限を越える|期限タイマー、書き込み直前の時計検査、復帰・定期的な利用状態再照会。期限切れ・照会失敗時は変更を拒否。閲覧は維持。|
|5. 期限切れの書き出し|実際の「書き出す」操作を入力制限から除外。模擬クラウド保存呼び出しを確認。読み込み・編集は制限を維持。|
|6. コピー保存失敗後の再試行|元データと分離した候補を保存し、成功してからメモリを更新。失敗後の再試行で欠落・二重登録がないことを確認。|
|7. バックアップの日付形式|パディングあり・なしを内部形式に正規化。不正日付・内容の異なる重複日付は読み込み前に拒否。|
|8. ワンタッチ削除の誤った成功表示|保存成功後だけ削除完了を通知。失敗時は元の一覧と保存内容を保持し、再試行可能。|

## 履歴・移行・バックアップ

- 既存の保存キーは移行元として残し、書き換え・削除しません。最初の保存成功から `hosshii_prelaunch_state_v2` に設定・シフト・目標を1回の同期書き込みで保存します。失敗時は成功表示にせず、旧データを維持します。
- 旧データには当時の変更履歴がないため、移行時に保存されている単価を移行前の基準値として凍結します。失われた過去の単価を自動復元するものではありません。
- 新規勤務先は基準値なし。日付確定前の金額は給与に適用しません。下書きを残して画面移動・再起動できます。
- 日またぎ勤務と時刻指定の有給は、翌日部分に翌日の設定を使用。日額交通費・手当は従来どおり出勤開始日に1回。月額交通費・手当は、承認済みの「給与締め期間の暦日数で日割り」を適用し、期間内の設定変更を反映します。勤務・有給のない期間への月額支給は従来どおり行いません。
- 締め日・給料日のルール自体の履歴化や、休憩を勤務中央に置く既存計算方法の変更は対象外です。
- バックアップは履歴・基準値・下書きを含むスキーマ2。旧形式は読み込み可能。未知の形式・履歴欠落は拒否し、既存データを上書きしません。新形式を旧アプリに読み込ませることはできません。

- 期限到達後の入力拒否、閲覧・書き出し、模擬paid応答による再開、再取得したトークン、通信失敗時の拒否と再確認を確認。
